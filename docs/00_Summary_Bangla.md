## ১. প্রজেক্ট ভিশন (01_Project_Overview)

**PlantHub Bangladesh** একটা মাল্টি-ভেন্ডর নার্সারি মার্কেটপ্লেস ও বিজনেস ম্যানেজমেন্ট প্ল্যাটফর্ম। উদ্দেশ্য — নার্সারি ব্যবসাগুলোকে Facebook/WhatsApp-নির্ভরতা থেকে বের করে এনে একটা সম্পূর্ণ ডিজিটাল সিস্টেমে নিয়ে আসা, যেখানে কাস্টমার প্ল্যান্ট কিনতে পারবে, এক্সপার্টদের সাথে পরামর্শ করতে পারবে, আর প্ল্যান্ট কেয়ার সম্পর্কে শিখতে পারবে।

**মূল লক্ষ্য:**
- বিশ্বস্ত অনলাইন প্ল্যান্ট মার্কেটপ্লেস
- নার্সারি ব্যবসা ডিজিটালাইজেশন (ইনভেন্টরি, অর্ডার, প্রাইসিং)
- অনলাইন প্ল্যান্ট কনসালটেশন
- প্ল্যান্ট নলেজ হাব ও ক্রিয়েটর ইকোনমি
- ভবিষ্যতে AI ফিচার যোগ করার জন্য প্রস্তুত আর্কিটেকচার

**স্কোপ:** Phase 1-এ (এখন) মার্কেটপ্লেস, নার্সারি ম্যানেজমেন্ট, ভেরিফিকেশন, কনসালটেশন (চ্যাট + ইমেজ রিভিউ), নলেজ হাব, নোটিফিকেশন, পেমেন্ট (COD + অনলাইন) থাকবে। AI ফিচার, ভিডিও কল, কুরিয়ার API, মাল্টি-ব্রাঞ্চ — এগুলো Phase 2/3-এ পিছিয়ে দেওয়া হয়েছে।

## ২. রিকোয়ারমেন্ট (02_Requirement)

সবগুলো ফিচারকে **ID** দিয়ে ভাগ করা হয়েছে (যেমন `FR-NUR-06`), যাতে পরে requirement, use case, API, আর টেস্ট কেসের মধ্যে সহজে সংযোগ করা যায়। মূল মডিউল:

- **FR-AUTH** — রেজিস্ট্রেশন, লগইন, JWT, RBAC
- **FR-MKT** — ব্রাউজ, সার্চ, ফিল্টার, উইশলিস্ট, বান্ডল, ক্যাম্পেইন
- **FR-NUR** — প্রোডাক্ট, ইনভেন্টরি, প্রাইসিং, অর্ডার, কাস্টমার ম্যানেজমেন্ট, অ্যানালিটিক্স, ইনভয়েস
- **FR-VER** — নার্সারি ও এক্সপার্ট ভেরিফিকেশন (৩ লেভেল)
- **FR-CON** — কনসালটেশন বুকিং
- **FR-KH** — ব্লগ, গাইড, কমিশন অ্যাট্রিবিউশন
- **FR-REV** — রিভিউ ও গ্রোথ টাইমলাইন (Day 1/30/90/180)
- **FR-NOTIF** — নোটিফিকেশন
- **FR-ADM** — অ্যাডমিন প্যানেল
- **FR-PAY** — পেমেন্ট

**নন-ফাংশনাল (মান/পারফরম্যান্স):** রেসপন্স টাইম টার্গেট, স্কেলেবিলিটি, সিকিউরিটি (পাসওয়ার্ড হ্যাশিং, HTTPS, RBAC মিডলওয়্যার), রিলায়েবিলিটি, মোবাইল-ফ্রেন্ডলি ব্যবহারযোগ্যতা।

## ৩. সিস্টেম অ্যানালাইসিস (03_System_Analysis)

৬টা মূল Use Case বিস্তারিতভাবে লেখা আছে: অর্ডার প্লেস করা, ইনভেন্টরি ম্যানেজ করা, কনসালটেশন বুক করা, নার্সারি ভেরিফিকেশন, গ্রোথ টাইমলাইন রিভিউ, ক্রিয়েটর কমিশন অ্যাট্রিবিউশন। প্রতিটা ইউজার রোলের (কাস্টমার, নার্সারি ওনার, এক্সপার্ট, অ্যাডমিন) জন্য User Story আকারে চাহিদাগুলো লেখা আছে।

## ৪. আর্কিটেকচার (04_Architecture)

**প্যাটার্ন:** Layered + Feature-Modular আর্কিটেকচার —
```
ক্লায়েন্ট → Express রাউট (Auth/RBAC/Validation) → Controller → Service (বিজনেস লজিক) → Repository (Prisma) → MongoDB
```
সাথে Socket.io (রিয়েল-টাইম), Redis (ক্যাশ/রেট-লিমিট), Cloudinary/S3 (মিডিয়া)।

**মডিউল:** auth, users, nurseries, products, inventory, pricing, orders, payments, reviews, experts, consultations, knowledge-hub, notifications, admin, analytics — প্রতিটা মডিউলের নিজস্ব ফোল্ডারে routes/controller/service/repository/validation/types/test ফাইল থাকবে, একই প্যাটার্নে।

**RBAC রোল:** এখন — Customer, Nursery Owner, Plant Expert, Admin। ভবিষ্যতের জন্য জায়গা রাখা হয়েছে — Delivery Partner, Affiliate, Nursery Employee ইত্যাদি।

**এখনো সিদ্ধান্ত বাকি:** ফ্রন্টএন্ড স্ট্যাক, হোস্টিং, পেমেন্ট গেটওয়ে অগ্রাধিকার।

## ৫. ডেটাবেস (05_Database)

Prisma + MongoDB দিয়ে পুরো স্কিমা লেখা আছে — User, NurseryProfile, ExpertProfile, Product, Inventory + InventoryLog, PriceTier, Order + OrderItem, Review + GrowthPhoto, Consultation + TimeSlot, Blog + CommissionAttribution, Wishlist, Follow, Campaign, Bundle, Notification। প্রতিটা কালেকশনের জন্য কোন ফিল্ডে ইনডেক্স দরকার আর কেন, সেটাও আলাদা টেবিলে আছে।

---

## ৬. API (06_API)

**Standards:** সব রেসপন্স একই ফরম্যাটে (`success/data/error`), পেজিনেশন, স্ট্যান্ডার্ড HTTP status code, রেট লিমিটিং, Idempotency key।

**মূল এন্ডপয়েন্ট গ্রুপ:**
- **Authentication** — register, OTP verify, login, refresh token, logout, password reset (JWT access ১৫ মিনিট, refresh ৭ দিন)
- **Plants (Products)** — browse/search/filter, CRUD, wishlist, ইনভেন্টরি আপডেট
- **Orders** — অর্ডার প্লেস করা, স্ট্যাটাস আপডেট (Pending → Confirmed → Packed → Shipped → Delivered, বা Cancelled/Returned), ইনভয়েস
- **Notifications** — সব নোটিফিকেশন টাইপের লিস্ট আর Socket.io ইভেন্ট কনট্র্যাক্ট

## ৭. UI/UX (07_UI_UX)

**ডিজাইন ফিলোজফি:** মডার্ন, প্রকৃতি-অনুপ্রাণিত, ক্লিন, ইমেজ-ফোকাসড, মোবাইল-ফার্স্ট। রেফারেন্স: Amazon (মার্কেটপ্লেস), Shopify (সেলার ড্যাশবোর্ড), Pinterest (ভিজ্যুয়াল ডিসকভারি)। কালার প্যালেট (সবুজের বিভিন্ন শেড), টাইপোগ্রাফি, প্রোডাক্ট কার্ড/ড্যাশবোর্ড/অর্ডার স্ট্যাটাস প্যাটার্নের গাইডলাইন দেওয়া আছে। এখনো ফাইনাল না — Figma-তে ডিজাইনার দিয়ে চূড়ান্ত করতে হবে।

## ৮. ডেভেলপমেন্ট (08_Development)

**BackendRoadmap.md** — ১০টা স্টেজে ভাগ করা checklist (Foundation → Auth → Product/Nursery → Orders/Payments → Engagement → Real-time/Notifications → Experts/Consultation → Knowledge Hub → Admin/Analytics → Launch Hardening)। **এটাই আপনার মূল ট্র্যাকার — যত কাজ করবেন, টিক দিয়ে যাবেন।**

**CodingStandards.md** — TypeScript strict mode, লেয়ার আলাদা রাখা (controller/service/repository), এরর হ্যান্ডলিং, ভ্যালিডেশন নিয়ম।

**GitWorkflow.md** — ব্রাঞ্চিং মডেল, কমিট ফরম্যাট, PR নিয়ম, এবং **দীর্ঘদিন পর প্রজেক্টে ফিরে আসলে কী করবেন তার ধাপ** (roadmap পড়া → git log দেখা → migration status চেক করা → Open Decision গুলো রিভিউ করা)।

---

## ৯. টেস্টিং (09_Testing)

Unit, Integration, End-to-End, Load টেস্টিং লেভেল সংজ্ঞায়িত। কোন ফ্লোগুলো লঞ্চের আগে অবশ্যই টেস্ট করতে হবে তার তালিকা (রেজিস্ট্রেশন, RBAC, অর্ডার স্ট্যাটাস ট্রানজিশন, পেমেন্ট idempotency ইত্যাদি), বাগ সেভারিটি লেভেল, আর লঞ্চের আগে কী কী শর্ত পূরণ হতে হবে (Exit Criteria)।

---

## ১০. ডিপ্লয়মেন্ট (10_Deployment)

CI পাইপলাইন (lint → type-check → test → build) ও CD পাইপলাইন (migrate → deploy → smoke test) প্রস্তাবিত। হোস্টিং অপশন (Railway/Render/DigitalOcean, MongoDB Atlas, Redis, Cloudinary) তালিকাভুক্ত আছে কিন্তু এখনো ফাইনাল সিদ্ধান্ত নেওয়া হয়নি — আপনাকে বেছে নিতে হবে।
